# 操作手册

本文件记录可重复执行的流程、清单和命令。

## 项目开始流程

适用场景：准备开始一个新项目、功能、文档、代码任务或研究任务。

### 输入模板

```text
我要做一个项目，请你先帮我定边界。

项目一句话：
我现在有什么：
我不懂的地方：
我希望最后得到什么：
哪些事情不能乱动：
```

### Codex 输出结构

```text
项目目标：
项目范围：
不做范围：
成功标准：
验收方式：
风险点：
需要用户拍板的地方：
Codex 可以自主决定的地方：
知识沉淀位置：
```

## 任务结束知识闭环流程

适用场景：每次完成一轮分析、写作、代码修改、方案设计或项目推进。

### 检查清单

- 是否形成了用户接受的决定？
- 是否发现了可复用经验？
- 是否产生了新的边界、禁区或约束？
- 是否形成了可复用流程、命令或检查方法？
- 是否体现了用户偏好？

### 路由规则

- 项目目标、范围、验收标准 → `00-项目边界.md`
- 已拍板选择 → `01-决策记录.md`
- 踩坑、根因、修复 → `02-经验教训.md`
- 可重复步骤 → `03-操作手册.md`
- 用户希望 Codex 如何配合 → `04-个人偏好.md`

### 最终回复要求

```text
知识库更新：
- 更新了：文件名
- 内容：一句话说明
```

如果没有可沉淀内容：

```text
知识库更新：KB-NOOP，原因：本轮没有形成可复用长期结论。
```

## 知识库与记忆系统设计重点

适用场景：希望让聊天中的稳定经验结论自动进入知识库，而不是停留在会话中。

### 核心原则

- `AGENTS.md` 负责声明长期规则和完成条件，但不是强制事务执行器。
- 权威知识应存放在 Git 管理的 Markdown 文档中，而不是只依赖模型记忆或聊天上下文。
- 原始会话只作为审计来源，不应默认全部注入上下文。
- 正确流程是：全量保存用于审计，增量提取用于写入，按需检索用于使用。

### 四层结构

- L0 会话事件库：保存用户消息、回复、工具证据和会话标识，只用于审计。
- L1 候选结论账本：保存本轮新增的原子结论和待确认项，只加载未闭环内容。
- L2 权威知识库：保存已接受、已验证、可复用的 Markdown 知识。
- L3 派生索引：全文索引、向量索引或知识图谱，只返回相关摘要和证据指针。

### 闭环流程

1. 从当前轮新增内容中提取候选结论。
2. 判断类型、范围和可信状态。
3. 去重并检查是否与已有知识冲突。
4. 写入对应权威文档，或标记为 `candidate`。
5. 更新可重建的检索索引。
6. 最终回复中说明更新了哪些知识文档；没有更新时说明 `KB-NOOP` 和原因。

### 关键边界

- `AGENTS.md` 是规则入口，不保存大量知识正文。
- Hook 适合做机械检查和闭环门禁。
- Skill 适合封装知识整理流程。
- MCP 或 CLI 适合做受控读写、检索、发布和验证。
- LangGraph、Mem0、Graphiti、向量库等框架属于增强能力，不是第一阶段必须项。

## 小白实现知识库的路线

适用场景：用户希望从零开始搭建一个能长期复用、能被 Codex 按规则更新的个人知识库。

### 第一阶段：先把 Markdown 知识库跑通

目标：不用复杂框架，只靠目录、文档和 `AGENTS.md` 形成基本闭环。

必备内容：
- `AGENTS.md`：写长期规则和完成条件。
- `知识库/00-项目边界.md`：记录目标、范围、验收标准和禁区。
- `知识库/01-决策记录.md`：记录已经拍板的决定。
- `知识库/02-经验教训.md`：记录踩坑、根因和修复经验。
- `知识库/03-操作手册.md`：记录可重复执行的流程。
- `知识库/04-个人偏好.md`：记录用户希望 Codex 如何配合。

每次任务结束必须检查：
- 本轮有没有稳定结论。
- 结论应该进入哪个知识文档。
- 是否已经写入。
- 最终回复是否说明知识库更新结果。

### 第二阶段：增加候选结论区

目标：防止不确定内容直接污染正式知识库。

候选结论状态：
- `candidate`：可能有用，但还没有确认。
- `accepted`：用户已经拍板接受。
- `verified`：已经被事实、测试或证据验证。
- `superseded`：已经被新结论替代。

### 第三阶段：再做自动检查

目标：让任务结束前自动检查有没有知识债务。

可选组件：
- Hook：做任务结束前的机械检查。
- CLI 或 MCP：负责检索、写入、发布和验证知识。
- Skill：封装知识整理流程。
- 全文索引或向量索引：只做召回，不做权威真相源。

原则：先养成知识闭环习惯，再逐步自动化；不要一开始就上复杂记忆框架。

## 个人知识库搭建步骤

适用场景：从零搭建一个给 Codex 长期使用的 Markdown 知识库。

### 搭建顺序

1. 建立根规则文件 `AGENTS.md`，只写长期规则、角色边界、知识闭环要求和最终回复要求。
2. 建立 `知识库/` 目录，按知识类型拆成项目边界、决策记录、经验教训、操作手册、个人偏好五类。
3. 给每类文档写固定模板，保证后续内容能按同一种格式追加。
4. 每次新任务开始时，先确认目标、范围、禁区、验收标准和决策权。
5. 每次任务结束前，判断是否产生稳定结论，并路由到对应知识文档。
6. 最终回复必须说明更新了哪些知识文档；没有更新时说明 `KB-NOOP` 和原因。

### 小白阶段不要先做的事

- 不要一开始搭建向量数据库。
- 不要一开始引入 LangGraph、Mem0、Graphiti 等复杂框架。
- 不要把所有聊天记录都塞进上下文。
- 不要把不确定推测直接写成正式知识。

### 第一阶段完成标准

- `AGENTS.md` 能清楚告诉 Codex 如何协作和如何落库。
- `知识库/` 下五类文档存在并可维护。
- 用户每次只需要下任务，Codex 负责判断是否需要沉淀。
- 最终回复能固定出现知识库更新结果。

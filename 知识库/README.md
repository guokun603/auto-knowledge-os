# 知识库总览

这个目录用于沉淀项目协作中形成的长期经验、规则、决策、流程和偏好。

原则是：

- 会话只是现场，知识库才是资产。
- 所有稳定结论都要落到文档，不只停留在聊天中。
- 不确定内容可以记录为 `candidate`，但不能伪装成事实。
- 新任务开始前，先读取和当前项目、模块、主题相关的知识。
- 任务结束前，检查是否产生了新的可复用结论。

## 目录结构

| 文件 | 用途 |
| --- | --- |
| `00-项目边界.md` | 记录项目目标、范围、禁区、验收标准和决策权 |
| `01-决策记录.md` | 记录已经拍板的关键决定，以及为什么这样选 |
| `02-经验教训.md` | 记录踩坑、根因、修复方法和以后如何避免 |
| `03-操作手册.md` | 记录可重复执行的流程、命令、检查清单 |
| `04-个人偏好.md` | 记录用户希望 Codex 如何协作、表达和执行 |

## 知识状态

| 状态 | 含义 |
| --- | --- |
| `candidate` | 候选结论，还需要验证或确认 |
| `accepted` | 用户已经接受，后续默认遵守 |
| `verified` | 已经通过证据、测试或实际结果验证 |
| `superseded` | 已被新结论替代 |

## 每次任务结束前检查

1. 本轮有没有产生可复用经验？
2. 本轮有没有做出以后要遵守的决定？
3. 本轮有没有形成新的项目边界、禁区或验收标准？
4. 本轮有没有形成可复用流程或命令？
5. 本轮有没有体现新的个人偏好？

如果答案为“有”，必须更新对应文档。
如果答案为“没有”，最终回复中说明：`KB-NOOP`，并给出原因。
